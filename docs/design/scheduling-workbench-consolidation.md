# 排课工作台整合实现规格

状态：已确认范围，供实现与验收使用

日期：2026-09-21

关联决策：`CONTEXT.md`、ADR-0017（排课工作面只保留在排课工作台）、排课流程优化设计。

## 1. 目标与边界

本次整合的目标是让排课工作台成为每次排课准备的唯一可发现工作面，同时把原“学期与作息时间表”“校历与排课准备”“基础数据”三个页面中仍然影响排课的能力接入工作台的相关上下文。工作台继续使用既有领域模型和 API，不新增一套向导进度、准备状态或平行数据模型。

这三个页面不能简单删除：学期生命周期、校历特殊日期、资源维护、导入和教师账号绑定中仍有不重复的职责。整合后的处理方式是：

- 工作台内提供当前排课所需的内嵌面板、快捷动作和问题修复入口。
- 原页面不再作为班级、科目、教师、作息、教学任务或自动排课的第二个维护入口；重复的导航项下线。
- 仍有独立业务价值的完整页面保留为兼容/高级维护入口，使用与工作台相同的组件、接口、权限和审计；页面之间不产生第二套状态。
- 旧书签、通知链接和外部深链接继续可用，先定位到工作台对应步骤或面板；兼容期内不以删除路由的方式完成收敛。

本规格不改变求解算法、排课规则模型、发布策略、角色定义、导入文件格式或学期中调课/代课模型。

## 2. 工作台目标信息架构

工作台仍保留五个排课步骤：`设置班级`、`设置课时`、`科目节数`、`教师任课`、`开始排课`。下表定义新接入的能力；步骤状态仍由当前业务事实实时推导，不保存独立流程进度。

| 能力 | 工作台位置 | 必须支持的动作 | 原页面处理 |
| --- | --- | --- | --- |
| 当前学期管理 | 工作台顶部学期上下文条的“学期管理”面板；可从任一步骤打开 | 创建中性学期、切换学期、查看状态/历史、编辑日期、复制指定内容；管理员可执行高风险删除 | `settings/semesters` 保留兼容/高级入口；不再作为排课准备的唯一入口 |
| 作息表容器与节次 | `设置课时`步骤；容器管理和宽表编辑在同一上下文 | 新增/选择/删除作息表容器，编辑分组、节次、时段、容量和免任课标记 | `/settings/period-tables/:id` 重定向到 `step=periods` 并保留 `table` |
| 校历与排课准备 | `开始排课`步骤的“校历与准备”面板 | 查看特殊日期，新增/编辑/删除停课和补课条目；查看阻断项与提醒；确认/撤回排课就绪 | `settings/calendar` 保留兼容/完整历史入口；两入口使用同一就绪检查和审计 |
| 教室/场地资源 | `开始排课`前置检查的“资源”抽屉，必要时可打开完整资源页 | 查看缺失/容量问题，新增/编辑/停用教室和场地，回到问题对象；不允许在此维护班级、科目或教师档案 | `basedata?tab=rooms` 保留兼容入口，打开同一资源组件 |
| 导入与来源数据 | 工作台“资源与导入”面板，或前置检查问题的上下文动作 | 选择模板/组合/参考文件，预览新增、未变化、修改和冲突，确认后单事务写入；查看来源、失败项和重新导入 | `basedata?tab=template|reference` 保留批量/历史操作入口；导入后的记录回到工作台对应档案视图 |
| 教师登录账号绑定 | “资源与导入”面板中的管理员专用区域 | 按现有教师完整对象绑定、解绑或修复登录账号；不得新增教师档案或修改任课 | `basedata?tab=accounts` 保留管理员专用入口，不向教务主任以外的角色暴露 |

“资源与导入”是工作台的聚合入口，不是新的资源领域。复杂批量预览、导入历史和账号安全操作可以在原完整页面完成，但必须在返回时保留当前学期，并在工作台刷新同一数据和就绪状态。

### 2.1 学期上下文面板

学期选择器在工作台所有步骤可见。面板至少包含：

1. 当前学期、起止日期、归档/当前状态和是否存在过期草稿。
2. 新建中性学期（学年、学期、真实起止日期），创建成功后将其作为工作台上下文。
3. 编辑现有学期日期，带日期校验和影响提示。
4. 复制学期及可选内容（作息表、科目、教师、教室、班级、年级升迁、约束配置、日期），预览目标和来源后一次提交。
5. 删除学期和作息表容器仅显示给有权限的管理员，并执行高风险确认；归档学期默认只读。

切换到历史/归档学期时，工作台允许查询和复制，不允许普通排课写入或发布。切换学期不得静默清除当前草稿或浏览状态。

### 2.2 校历与排课准备面板

面板必须复用日历 API 和排课前置检查：

- 特殊日期条目包含日期、类型（停课/补课）、关联周次或星期信息、说明和来源；编辑前显示影响的课表范围。
- “排课就绪”只表示当前检查没有阻断错误，不激活规则、不创建课表草稿、不表示已发布。
- 详情中区分阻断错误和提醒，每一项给出影响对象、数量和可直接执行的修复动作。日期缺失或资源缺失应直接打开对应的工作台面板，而不是把用户带到失效页面。
- 教务主任或管理员可以确认就绪；同样角色可以撤回确认。确认和撤回必须使用现有状态、版本和审计记录。
- 导入、日期、作息、教学任务、资源或规则发生会影响排课的变更后，自动回到“待确认”，受影响草稿标记为过期；不删除已发布快照。

## 3. 日期编辑缺口修复

当前工作台在遇到学期日期问题时能够定位到学期页面，但现有学期页面只展示日期，不能修改已有学期。实现必须补齐现有学期日期编辑，不得要求删除并重建学期。

### 3.1 行为契约

- 编辑入口位于学期上下文面板；前置检查的日期问题提供同一入口并保留原步骤、滚动位置和问题上下文。
- 开始日期和结束日期均为真实日期，必须满足 `start_date <= end_date`；无效日期、越界日期和空值在提交前阻断。
- 只允许对当前可写学期编辑。归档学期、非当前历史学期和无写权限用户只能查看；权限判断在动作 API 和目标组件中都执行。
- 日期更新成功后刷新学期上下文、校历摘要、五步状态和草稿新鲜度；不能自动修改已发布课表快照。
- 若学期已有草稿、已就绪确认或已发布记录，提交前说明影响并要求显式确认；写入后按既有同步规则撤回就绪、标记相关草稿过期并记录审计。
- 保存失败保留用户输入和错误信息，不产生部分日期更新。

### 3.2 接口与数据复用

优先接入既有 `updateSemester`（或后端等价接口），不要在前端维护第二份日期状态。更新响应应返回最新学期摘要或可用于刷新上下文的版本号。若后端已有能力但前端未暴露，只补齐调用、权限提示和测试；只有确认接口不存在时才按现有学期 API 风格补充接口。

## 4. 资源、导入与数据一致性

### 4.1 资源维护

工作台只提供当前排课所需的资源动作：查看资源缺口、快速新增/修正教室或场地、重新运行前置检查。教室容量不足属于提醒或阻断项时，面板要显示受影响的教学任务和可选资源。资源更新使用既有资源接口，成功后刷新工作台，不把资源复制为学期内另一份对象。

### 4.2 导入

- 模板导入、组合基础数据导入和参考文件导入都保留各自的来源归属、预览和权限边界。
- 预览结果至少区分新增、未变化、将修改、冲突和无法写入项；确认写入必须是一个事务，失败不得留下半批数据。
- 导入不会自动激活排课规则、确认就绪或创建课表草稿；导入完成后重新计算工作台状态。
- 导入班级、科目、教师或教室后，记录可在工作台同一档案/资源视图继续编辑；不新增“导入后专属页面”。
- 参考文件的查看、重试和历史记录可以留在完整导入页，但工作台需显示来源和最后一次结果。

### 4.3 一致性与并发

所有面板使用同一当前学期上下文和后端版本/更新时间。提交前若检测到版本变化，提示重新加载，不能用旧表单覆盖较新的数据。删除、复制、导入和账号绑定等动作完成后重新拉取相关摘要，不能只修改局部前端计数。

## 5. 兼容路由与导航

### 5.1 新入口

新导航只突出“排课工作台”。原三个页面不再与工作台并列作为排课准备的第一入口；工作台面板使用以下稳定上下文参数（参数名可按现有路由规范实现，但语义必须保持）：

```text
/scheduling/flow?step=<classes|periods|subjects|teachers|start>
  &semester=<semester-id>
  &table=<period-table-id>
  &view=<archive|assignments|calendar|resources|semester>
```

`view` 只决定当前步骤中的业务视图，不保存向导进度。面板关闭或刷新后仍可根据学期事实重新推导状态。

### 5.2 旧地址

兼容重定向必须保留有效的 `semester`、`view`、`table`、来源问题和必要筛选条件；重定向不是授权边界，目标动作必须再次执行原有角色检查。

| 旧地址 | 目标上下文 |
| --- | --- |
| `/basedata?tab=classes` | `step=classes`、班级档案视图 |
| `/basedata?tab=subjects` | `step=subjects`、科目档案视图 |
| `/basedata?tab=teachers` | `step=teachers`、教师档案视图 |
| `/scheduling/assignments` | `step=teachers` 或请求的任课/科目视图 |
| `/scheduling/auto` | `step=start` |
| `/settings/period-tables/:id` | `step=periods&table=:id` |
| `/settings/semesters` | 学期管理面板，带 `semester` 上下文 |
| `/settings/calendar` | `step=start` 的校历与准备面板 |
| `/basedata?tab=rooms|template|reference|accounts` | `step=start` 的资源与导入面板，并保留对应子标签 |

若用户直接进入完整的高级维护页面，页面必须显示当前学期、权限和“返回排课工作台”动作，并在写入后刷新工作台数据。兼容路由在至少一个迁移周期内保留；只有确认没有独特能力、无外部引用且回归测试覆盖后，才可删除旧页面实现，不能删除兼容地址。

## 6. 权限、确认与审计

权限以当前学校、当前学期和现有角色检查为准。前端隐藏按钮不等于授权，所有动作在 API/服务层再次检查。

| 动作 | 教务主任 | 内置管理员 | 教师/其他 |
| --- | --- | --- | --- |
| 查看当前和历史学期、校历、资源、导入结果 | 可 | 可 | 按既有只读范围 |
| 创建/切换/编辑当前学期日期 | 可 | 可 | 不可 |
| 复制学期、维护当前作息表、特殊日期、资源和导入 | 可 | 可 | 不可 |
| 确认/撤回排课就绪 | 可 | 可 | 不可 |
| 删除学期或作息表容器 | 不可 | 可，当前可写学期且高风险确认 | 不可 |
| 教师登录账号绑定/解绑 | 不可 | 可，管理员专用 | 不可 |
| 排课规则激活、生成草稿、发布 | 沿用现有规则 | 沿用现有规则 | 不可 |

每个写入动作至少记录：操作者、角色、学校和学期、动作类型、目标 ID、前后摘要/变化数量、来源入口（工作台或兼容页）、请求时间、结果和失败原因。以下动作必须保留确认和审计：学期/作息表删除、学期复制、日期修改对现有草稿的影响确认、导入提交、就绪确认/撤回、账号绑定/解绑。审计中不得记录明文密码或导入文件中的敏感凭据。

## 7. 实现拆分与非功能要求

建议按以下顺序实现，提交可以拆成多个独立变更：

1. 扩展工作台上下文条和面板路由，接入学期选择、日期编辑和作息表容器动作。
2. 将校历特殊日期、就绪详情/确认/撤回接入 `开始排课`，统一问题修复入口和状态刷新。
3. 将资源、导入和管理员账号绑定接入工作台聚合面板，复用原页面组件；保留高级完整页。
4. 添加兼容重定向、导航收敛、权限/高风险确认和审计字段。
5. 补齐回归测试、文档中的入口说明和旧链接验证，再评估删除未被引用的重复视图实现。

实现必须满足：

- 异步加载、空状态、错误和权限不足状态可区分；写入失败不丢失表单输入。
- 面板在桌面和窄屏下不遮挡流程栏、问题详情和保存动作；长列表支持滚动和键盘操作。
- 重复点击提交、刷新或浏览器后退不会创建重复学期、重复导入或重复特殊日期。
- 组件可以被独立页面复用，不能通过复制表单和状态管理形成第二套业务逻辑。

## 8. 验收标准

### 8.1 工作台与功能覆盖

- 从工作台可以选择/创建当前学期，查看状态和历史，并在不离开工作台的情况下编辑有效日期。
- 日期问题的修复动作直接打开日期编辑面板；日期校验、权限、影响提示、就绪撤回和草稿过期标记均可验证。
- `设置课时`可以新增、选择、编辑和删除作息表容器，并能从旧作息表地址定位到相同上下文。
- `开始排课`可以查看、创建、修改和删除校历特殊日期，显示阻断项/提醒，并完成就绪确认和撤回；两种入口的状态和审计记录一致。
- 工作台可以打开资源、模板/组合/参考导入和管理员账号绑定；导入有预览、冲突、事务提交和来源结果，账号绑定不会暴露教师档案维护。
- 班级、科目、教师、教学任务和自动排课仍只有工作台一个可发现维护入口，档案和资源数据不会出现重复记录。

### 8.2 路由、权限与审计

- 所有既有兼容地址按路由表保留并传递学期、视图、作息表和问题上下文；直接访问和重定向访问得到相同权限结果。
- 教务主任、管理员和教师的允许/拒绝矩阵有自动化测试；前端隐藏与后端拒绝均覆盖。
- 删除、复制、日期变更、导入提交、就绪确认/撤回和账号绑定均产生可查询审计记录；高风险动作缺少确认时不会写入。
- 归档或非当前学期无法进行常规写入；已发布课表保持快照不被日期、资源或导入修改。

### 8.3 一致性与回归

- 任何影响排课输入的变更都会让就绪状态回到待确认，并将相关草稿标记为过期，但不删除草稿或已发布课表。
- 并发版本变化会提示重载而不是静默覆盖；事务失败不会留下部分导入、复制或删除结果。
- 现有工作台五步骤、课程表调整、版本与发布、导入预览、校历和学期管理测试全部通过；新增兼容路由和移动/窄屏布局回归通过。

## 9. 完成定义

当第 8 节验收标准全部通过，导航和文档已将工作台标为唯一排课准备入口，三个旧页面仅承担明确列出的独立职责并可通过兼容地址访问，且没有发现重复的前端表单、状态或后端模型时，才可评估移除未再使用的旧页面实现。删除页面文件本身不是本次整合的验收条件。
