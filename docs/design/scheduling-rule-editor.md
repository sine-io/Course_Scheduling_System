# 排课规则编辑器设计建议

状态：设计建议，待产品确认。

## 结论先行

本系统不应该设计成“输入任意一句话，然后直接排课”的规则编辑器。更适合的形态是：

- 用一组可理解的规则模板编辑结构化条件；
- 同时保存教务人员的原文、文件位置和解释；
- 导入 Word/Excel 时先生成规则候选，由人确认后才加入规则集版本；
- 将规则编译成求解器可用的硬约束或软目标，并给出冲突和影响预览；
- 删除规则只在新的草稿版本中停用，已经发布的课表仍固定使用原版本。

这样既能容纳规则的频繁变化，也不会把不确定的自然语言误当成确定约束。

## 1. `排课规则.docx` 的内容拆分

这份文件并不是一种数据。建议导入时按下面的边界处理：

| Word 内容 | 应归属 | 在编辑器中的处理 | 当前系统缺口 |
| --- | --- | --- | --- |
| 行政会周一早晨第一节 | 全校禁排/保留时段 | 必须满足，选择作息表和“上午第 1 个教学时段” | 现在用所有教师不可用来近似，缺少全校时段语义 |
| 班主任会周一下午第二节及指定班主任 | 教师组禁排时段 | 必须满足，教师多选 + 下午第 2 个教学时段 | 只能硬编码教师姓名和课号 |
| 语数英优先上午前 3 节，体音美可下午 | 科目时段偏好 | 尽量满足，科目/年级多选 + 时段窗口 | `S5` 只按 `is_major` 粗略处理 |
| 语数英一周某天 2 节、其他天 1 节、连堂偏好 | 科目分布与连堂 | 分拆成“每周分布”“连续时段”“教研日例外”三条规则 | 当前没有通用分布和例外表达 |
| 周一/三/四/五教研日 | 科目禁排时段 | 按科目和星期选择必须避开或尽量避开，并可只限制上午 | 导入结果目前只是原文记录 |
| 体育从第 3 节开始 | 科目时段窗口 | 体育课第 1、2 节禁止，必须满足或可配置为尽量 | 目前只有未生效的原始窗口 |
| 音乐、美术、机房、理化生实验室错峰 | 教室资源 + 教师不冲突 | 教室类型、可用数量和同一教师不可重叠；连续授课另设偏好 | H3 已有部分能力，容量仍只是前置提醒 |
| 跨年级教师尽量同一时段只在一个年级 | 教师跨年级切换偏好 | 尽量满足，按教师和年级分组计算切换代价 | 只有教师不能重叠，没有切换目标 |
| 单双周课表 | 周期规则 | 选择单双周模式、课时归属和例外 | `Problem` 没有周次维度，不能假装已经支持 |
| 动静结合 | 科目类别相邻/分布偏好 | 给科目标记主科、副科、活动等类别，惩罚不合理相邻 | 目前没有类别相邻模型 |
| 七、八年级国防体育周二至周五第 3、4 节一次，教师刘锴 | 教学任务 + 固定时段规则 | 教学任务填写每周 1 次、教师和科目；时段规则必须满足 | 导入虽创建任务和原始窗口，但窗口尚未编译 |
| 各年级“35 节/34 节”和科目课时 | 教学任务/课程计划 | 进入教学任务，排课前校验总课时；不作为自由规则 | 九年级文本合计与标题不一致，不能静默覆盖 |
| 走教教师、幼儿园、孟召磊/路兆宇等个人要求 | 教师日程或教师偏好 | 明确对象后分别录入不可用、避开、连堂或半天空闲 | 当前依赖导入器中的姓名硬编码 |

导入器应把“规则原文”和“教学任务数据”分开。课程名称、教师、班级、每周课时、连堂数量属于教学任务；“必须避开周一第一节”才是规则。

## 2. 规则处理链路

```text
人工录入 / Word / Excel
          |
          v
原文快照（文本、文件哈希、段落或单元格位置）
          |
          v
规则候选（模板、对象、时段、强度、状态、置信说明）
          |
          v
教务确认 / 修改 / 停用
          |
          v
规则集版本（草稿 -> 生效；历史版本不可变）
          |
          v
纯规则编译器 -> 求解器 Problem -> CP-SAT
          |
          v
前置检查、冲突诊断、排课结果和规则版本快照
```

任何不能映射到受支持模板的内容，都必须显示为“待确认”或“不支持”，并进入前置检查报告；不能因为解析失败而被当成普通备注后悄悄忽略。

## 3. 规则的最小结构

编辑器面向人展示模板，后端保存统一的规则对象。建议字段如下：

| 字段 | 含义 |
| --- | --- |
| `template` | 规则模板，如 `global_blackout`、`time_window`、`distribution` |
| `target` | 对象类型和选择器：全校、年级、班级、教师、科目、教学任务、教室或资源组 |
| `timing` | 作息表、星期、教学时段序号/早午时段、起止时间、单双周；不能只依赖一个裸课号 |
| `operator` | 禁止、要求、偏好、避开、至多、至少、恰好、连续、不同日、同时或错开 |
| `strength` | `hard`、`soft`、`informational` |
| `weight` / `priority` | soft 规则的相对重要程度；默认用“高/中/低”，避免让用户直接调求解器分数 |
| `params` | 模板专属参数，如每日上限、连续节数、每周次数、资源容量 |
| `status` | 草稿、待确认、生效、停用、不支持或无效 |
| `source` | 手工/Word/Excel/系统来源、原文、文件位置、指纹 |
| `compiler_version` | 解释该规则所需的编译器版本 |

概念示例（不是要求用户直接编辑 JSON）：

```json
{
  "template": "global_blackout",
  "target": {"entity_type": "school"},
  "timing": {
    "period_table_ids": ["regular-table"],
    "weekdays": [1],
    "period_ordinals": [1],
    "period_types": ["morning"]
  },
  "operator": "forbid",
  "strength": "hard",
  "status": "active",
  "source": {"kind": "docx", "text": "行政会周一早晨第一节", "location": "第 2 段"}
}
```

```json
{
  "template": "distribution",
  "target": {"entity_type": "subject", "ids": ["数学", "语文", "英语"]},
  "timing": {"weekdays": [1, 2, 3, 4, 5], "exclude_weekdays": [3]},
  "operator": "prefer",
  "strength": "soft",
  "params": {"one_double_day": true, "other_eligible_days": 1, "prefer_blocks": [[1, 2], [3, 4]]}
}
```

## 4. 编辑器交互

### 4.1 规则列表是主入口

页面打开先显示规则列表，而不是一块空白文本框。每行至少显示：对象、规则摘要、强度、状态、来源、所属版本和最近修改人。筛选条件包括：

- 全校、年级、班级、教师、科目、教学任务、教室资源；
- 必须满足、尽量满足、仅作记录；
- 生效、草稿、待确认、不支持、冲突；
- 手工、Word、Excel、系统默认。

### 4.2 新建规则采用五步表单

1. **选择对象**：全校、教师、教师组、班级、年级、科目、教学任务或教室资源。
2. **选择模板**：禁排时段、固定课位、时段偏好、每日/每周上限、连堂与不连堂、科目分布、同时/错开、资源条件、周期规则。
3. **选择范围**：目标对象、作息分组、例外对象和适用学期。
4. **选择时间和参数**：星期、上午/下午、教学时段序号或起止时间、每周次数、连续节数、单双周等。
5. **确认强度**：必须满足、尽量满足或仅作记录；尽量满足时选择高/中/低优先级，并填写给教务人员看的解释。

表单旁边实时显示人类可读摘要，例如“七年级的国防体育每周 1 次，周二至周五第 3-4 节（必须满足）”。保存前展示影响预览：匹配的教学任务、被排除的候选时段、可能出现的硬冲突以及受影响的教师和班级数量。

### 4.3 导入确认

Word/Excel 预览页按“已识别课程”“规则候选”“无法识别内容”分栏。每条候选可以确认、修改模板、改成尽量满足、停用或保留为备注；页面必须显示原文和来源位置。导入提交只创建新草稿版本，不直接改写正在使用的版本。

### 4.4 规则详情和停用

详情页同时展示结构化条件、原文、编译支持、冲突诊断和生效版本。删除按钮的语义是“在下一版本停用”；历史版本和已经发布的课表仍可查询，不能物理删除规则证据。

## 5. 与现有求解器的结合

规则编辑器不应让 `model_builder.py` 直接读取数据库行。建议增加一个纯领域边界：

```text
RuleCompiler.validate(candidate, problem_context) -> diagnostics
RuleCompiler.compile(active_rules, problem_context) -> compiled_rules
```

`solver_data.py` 负责把某个规则集版本加载成纯对象；`RuleCompiler` 负责解析模板、检查对象是否存在、展开时段和例外，并产出 `CompiledRules`。`model_builder.py` 只消费 `CompiledRules`，把 hard 规则加入可行域/约束，把 soft 规则加入目标项，把 informational 规则交给报告层。

与当前实现的对应关系：

| 现有能力 | 迁移方式 |
| --- | --- |
| `TeacherTimeRule` | 映射到教师不可用、避开、偏好模板 |
| `BlockRule` | 映射到连堂/连续模板 |
| `ConstraintConfig` | 保留为求解参数兼容入口，逐步映射为每日上限和 soft 权重 |
| `ReferenceSchedulingRule` | 只保存导入原文和证据，形成规则候选，不直接驱动求解 |
| H1-H10 | 作为系统内置硬约束，规则模板不能绕过 |
| S1-S8 | 作为已有 soft 目标的实现，可由模板增加更细的目标项 |

需要优先修正的现状：教研日、体育起始节、主科上午、国防训练时段目前在导入结果中多是未生效的原始窗口；“全校会议”用全体教师禁排近似也不能表达一个真正的全校保留时段。规则编译器上线前，前置检查应明确显示这些内容的状态。

## 6. 版本、接口和审计

建议数据关系为：

```text
scheduling_rule_set (semester_id, active_revision_id)
  -> scheduling_rule_revision (revision_no, status, created_by, created_at)
       -> scheduling_rule (template, target, timing, operator, strength, params, source, status)
```

规则集版本需要被排课任务、课表草稿和已发布课表引用。新增、修改、停用规则都在草稿版本中完成，激活时记录操作者、说明、诊断结果和编译器版本。

建议接口：

- `GET /rule-types`：返回模板目录和表单元数据；
- `GET /rule-sets/{id}/rules`：查询某版本规则；
- `POST/PUT /rule-sets/{id}/rules`：新增或修改草稿规则；
- `POST /rule-sets/{id}/validate`：返回无效条件、冲突和不支持项；
- `POST /rule-sets/{id}/preview`：返回影响范围和候选时段变化；
- `POST /rule-sets/{id}/activate`：生成/激活新版本并记录审计。

自动排课接口应接收明确的 `rule_set_revision_id`；排课结果不能隐式使用“当前最新规则”，否则同一份输入无法重现。

## 7. 第一版模板范围

建议第一版只做可以解释、校验和测试的模板：

1. 全校禁排/保留时段；
2. 教师不可用、避开和偏好时段；
3. 年级/班级/科目时段窗口；
4. 固定课程或固定课位；
5. 每日/每周上限、下限和恰好次数；
6. 连堂、连续和不连续；
7. 科目跨日分布；
8. 同时、错开和简单顺序关系；
9. 教室类型、设备和可用数量。

单双周、动静结合的复杂邻接、跨年级切换优化和容量硬约束可以作为后续模板，但在模型支持前应明确标为“不支持”，不能只存一段说明就显示为已生效。

## 8. 实施顺序和验收

### P0：模型和导入边界

- 建立规则集、版本、规则候选和来源字段；
- 建立模板目录、状态和诊断结构；
- 把 Word 导入从“硬编码直接写规则”改为“候选预览”；
- 实现 `RuleCompiler.validate/compile` 的最小闭环；
- 让排课任务保存规则集版本。

### P1：可用编辑器

- 完成第一版九类模板的列表、表单、影响预览和审计；
- 把现有教师时间规则、连堂规则和标量参数接入兼容适配器；
- 为每条 soft 规则显示未满足原因和目标贡献；
- 增加独立课表校验器，检查求解器输出是否违反 hard 规则。

### P2：扩展表达能力

- 增加周次/单双周维度；
- 增加科目类别相邻和跨年级切换目标；
- 将教室容量从前置提醒提升为可配置硬约束；
- 新规则必须通过新增模板和测试进入系统，不开放任意用户代码。

验收至少覆盖：行政会不会被安排课程、体育不会出现在前两节、教研日规则能按科目生效、国防训练时段和教师一致、停用规则只影响新版本、同一规则版本可以重现同一排课输入，以及无法表达的单双周规则会明确报警而不是被忽略。

## 9. 需要产品先定的边界

1. 已发布课表是否永远固定规则版本：建议是；规则修改只影响新草稿和重新排课。
2. 单双周是否进入第一版：建议先保留导入和提示，等 `Problem` 增加周次维度后再激活。
3. 是否允许直接输入自然语言：建议允许作为“规则候选说明”，但必须选择模板并确认后才能执行。
