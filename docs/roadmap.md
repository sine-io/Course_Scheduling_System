## v1.1 范围(依实现顺序)

### 1. E2E 硬编日期到期修复 —— S,**有死线:2026-11 前**

- **问题**:多支 e2e spec 硬编未来日期(`2026-11-11`、学期 2026-09..2027-01);真实日期越过后
  `clock.is_past_slot` 会拒绝代课指派,**CI 将无声转红**。
- **影响谁**:所有贡献者——CI 一红,其他回归都看不见了。
- **做法**:以「今天起算的下一个周三」动态生成请假日,学期起止跟着今天推算。
- **不做的后果**:2026-11-11 起 CI 全红,E2E 防护网等于拆掉。

### 2. 后台任务队列拆分(default / ops)—— M/L,v1.1 旗舰项

- **问题**(M5 复审 A 正解):单一 RQ worker 循序执行;60 班自动排课跑数分钟期间,
  排课管理员按「导出课表」「立即备份」会排队到超时失败。数据安全洞已用 cancel-on-timeout +
  恢复前 409 封死,但**体验洞还在**——排课季正是导出最频繁的时候。
- **影响谁**:排课季的排课管理员,几乎必踩。
- **做法方向**:`ops` 队列(导出/备份/恢复)+ 第二个 worker 容器(同一 worker 镜像、
  `command: worker --queue ops`)。排课永远只走 `default`,故 ops worker 不会加载 ortools 的
  求解路径,内存预算约 +512MB(`docker-compose.limits.yml` 同步调整)。
  需更新:compose(5→6 容器)、`solver_busy()` 的队列范围、部署/升级文件、备份恢复的 409 判定。
- **先做的理由**:牵动容器架构与内存预算,后面所有项目的文件与 E2E 都叠在确定后的架构上。
- **不做的后果**:每个排课季都有排课管理员报告「导出坏掉」,对信任的伤害最大。

### 3. 部分排课三合一(排不下的课不再炸整锅)—— M

三项同一子系统,一次做完:

- **3a. 候选为空先 raise、轮不到 drop**:`model_builder` 对「完全找不到可排时段」的课直接
  `SolverInputError` → 整个部分排课失败。但部分排课的承诺就是「排不下的列列表、其他照排」。
  改为:建模前把候选为空的课移入未排列表,其余正常建模。
  **不做的后果**:数据越难排的学校,越用不了为他们设计的功能。
- **3b. 未排列表持久化**:目前只活在 Redis(24h TTL,`progress.py`);部分排课草稿可被 force
  发布,之后**没有任何记录**说哪些课没排。改为随草稿版本存 DB(新表或版本 JSON 栏),
  报表与日后查询都需要它。
- **3c. 群组未排数重复计数**:`_unscheduled()` 按 assignment 逐项记录,走班群组少排一个时段会被记为 N 项。
  按排课单位(group)去重。
- **验收**:含一个「有课完全排不下」的 e2e / 整合测试,确认列列表而非失败。

### 4. 开新学期复制补全 —— S(两项一起)

- `semester_copy.py` 确认**不带学期起止日、不带 `constraint_config`**(软约束权重回默认)。
  复制对话框加起止日字段、`constraint_config` 随复制带过去(或加勾选)。
- **影响谁**:每学期交替时的每一位排课管理员(一年至少两次,必踩)。
- **不做的后果**:新学期忘了补起止日 → 请假/代课的「今日」判定全错,查因很痛。

### 5. 小型加固批量 —— 全部 S,凑一批出货

| 项目 | 现状(已验证) | 做法 |
|---|---|---|
| 班级名称唯一性 | `ClassUnit` 无 uq,可建两个「301」 | 加 `uq(semester_id, name)` + 迁移前清重复 + API 409 |
| `/api/docs` 正式环境公开 | `main.py` 无条件开 | 默认关闭,`.env` 显式打开(开发 compose 带开) |
| 主色对比未达 AA | Naive 默认绿 `#18a058` 白字 ≈3.4:1 | 主色调深至 ≥4.5:1(如 `#0d7a43` 一带),a11y 测试门槛同步提到 4.5 |
| 冲突定位不理会取消 | `conflict_explainer` 无 `should_stop` | 把 control 传进逐步试解循环,按取消得到 cancelled |
| `check_feasibility` 吞错误信息 | `except SolverInputError: return "infeasible"`(model_builder:968) | 信息记 log + 附进 conflict detail,建模 bug 不再伪装成「数据无解」 |
| 列表查询保护性上限 | `audit-logs` 有 limit(≤500);`substitution-log`/`leaves` 无上限 | 先加服务器端上限(如 1000)防整年数据整包拉;完整分页 UI 留 v1.2 |

## v1.2+(明确延后,不是忘记)

- **完整列表分页**(UI + offset):单校一学期的量还撑得住,先靠上限保护;整年数据变慢时再做。
- **restore-upload 流式写入**:`await file.read()` 会把整个文件读入内存;现有 Caddy 200MB 上限 +
  「超大 DB 走 volume 复制法」文件已缓解。
- **恢复溯源 `restore.log` + stale 警告持久徽章**(M5 复审 G):presafe 文件名时戳暂可佐证。
- **CORS 文件化**:Backlog 说「不可由 .env 设置」——**不精确**:`cors_origins` 是
  pydantic-settings 的 list 字段,本来就能用 env(JSON 格式)覆盖,只是没文件、没验证。
  v1.2 补文件与格式验证即可,同源部署下本项无实害。
- **前端 bundle 瘦身**(1.4MB,`app.use(naive)` 全量注册):校内网冷载 ~1 秒可接受;
  改按需导入时记得 e2e 全跑一次。
- **api 镜像拆掉 ortools**(660MB→约 200MB;已确认 ortools 在主依赖、api 容器用不到):
  搬到 `[export]` 之类的 extra 由 worker 安装;对频宽敏感的部署才有感。
- **求解前 hard-only 探测 + warm start;部分排课独立短时限**:解质量/速度优化,独立可做。
- **教学任务 API 直接挡群组节数不一致(409)**:pre-flight 已挡(`group_shape_mismatch`),
  API 层再挡只是把错误提早到创建当下。
- **工程卫生**:`test_purity` 补相对导入扫描;`slots_overlap`/`course_key` 补边界单元测试;
  **评估后端依赖锁定**——pyproject 全为 `>=` 无上限,镜像重建即静默升级主版号
  (2026-07-13 CI 首跑实例:redis-py 8 让 RQ 阻塞取结果失效,导出 500;
  本机因 pip layer 缓存测不到)。至少对 redis/rq/sqlalchemy/fastapi 加上限或引入 constraints 文件。
- **科目导入加 `is_major` 栏**:表单已可勾,导入字段是便利性。

## v2(需要外部条件)

- **企业通讯平台通知适配器**：通过 webhook 对接企业微信、钉钉等学校已采用的平台。
  等试用学校提出明确需求并提供测试环境后再实现。
- **软约束权重 UI**:`GET/PUT /api/solver/config` 已在,滑杆是给高级用户的;
  等有学校真的想调权重再开工。

## 刻意不做(除非出现真实个案)

- **“一门课逐节更换教室”**：现行 `y[教学任务, 教室]`（一门课整学期使用一间教室）符合多数中学的实际安排，
  变量量小;改 `y[教学任务, 节次, 教室]` 是为了不存在的需求付模型复杂度。
- **`teacher_time_rule` 墙钟化(加作息时间表维度)**:v1 已确定「以该教学任务班级的作息时间表解读」,
  单作息时间表学校(绝大多数)无此问题;等真的出现「跨部授课教师 + 两套作息时间表」的学校再改 schema。
