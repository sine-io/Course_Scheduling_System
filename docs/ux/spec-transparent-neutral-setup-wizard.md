# 透明的中性学期初始化（历史规格）

状态：本文的运行时流程部分已由 [ADR-0010](../adr/0010-distributed-semester-preparation.md) 取代。保留本文件是为了记录中性学期数据决策；当前产品不提供独立的设置向导、向导进度或设置完成状态。

## 仍然有效的领域决策

- 创建学期只产生带真实起止日期的中性学期外壳，不选择学校级学制模板，也不隐式生成科目、教师、班级或作息。
- 班级、作息分组、科目和教师在排课工作台的对应步骤维护；教室/场地、导入、校历和教师账号等独立职责集中到工作台的“资源与导入”“校历与准备”辅助工作面。每个页面保存真实业务数据，用户可以按任意顺序返回修改。
- 班级的学制和作息分组可以混合配置。任何快捷起稿都必须展示可见参数、预览和显式确认，不能把模板选择当成学校全局学制。
- 教师账号创建属于账号权限管理，不属于学期基础数据初始化；批量导入 API 的兼容边界与页面维护工作面保持分离。
- 排课前置检查、排课准备确认和课表发布分别由排课领域负责，不因学期创建而自动通过。

## 当前用户旅程

1. 管理角色在“排课工作台”创建或选择当前学期。
2. 在工作台依次维护班级、作息、科目节数和教师任课。
3. 按需在工作台的“资源与导入”辅助工作面导入数据、维护教室/场地或绑定教师账号，并在“校历与准备”辅助工作面配置特殊日期。
4. 在工作台的“开始排课”步骤处理前置检查，再生成、调整和发布课表。

这些页面不共享一套跨页面进度。仪表盘只显示当前学期已有数据摘要，并把事实性提醒链接到对应业务页面。

## 历史背景

旧规格曾设想把以上动作串成四步向导，并提供完成页、保存续作和重新进入入口。该方案在实现前被移除，因此不需要为旧向导保留升级兼容或数据迁移；历史 Alembic 迁移仍按数据库演进记录保留。
