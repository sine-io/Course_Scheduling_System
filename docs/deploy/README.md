# 部署与运维手册

给**学校信息管理者/排课管理员**的完整操作文件。系统为单校自建、纯 Web,以 Docker Compose 一键部署,六个容器(web / api / worker / worker-ops / postgres / redis)在一台主机上跑完。

> `worker` 专跑自动排课(一次可跑好几分钟),`worker-ops` 跑导出、备份、恢复、发送邮件与定时任务。分开的用意是:**排课那几分钟里,你按「导出课表」仍然是立即响应的**。

## 三分钟理解这套系统怎么跑

```
                 用户浏览器
                      │  http://校内主机IP
              ┌───────▼────────┐
              │  web (Caddy)   │  静态前端 + 反向代理 /api
              └───────┬────────┘
                      │
        ┌─────────────▼──────────────┐
        │  api (FastAPI)             │  登录、数据维护、手动排课、报表
        └───┬──────────────────┬─────┘
            │                  │
     ┌──────▼──────┐    ┌──────▼───────┐
     │ postgres    │    │ redis        │  队列 + session 时效
     │ (你的数据)  │    └──────┬───────┘
     └─────────────┘           │
            ▲            ┌──────▼───────┐
            └────────────┤ worker       │  自动排课、发送邮件、PDF 导出、每日备份
                         └──────────────┘
```

- **你的数据只在 `postgres`**(存于 Docker volume `pgdata`),备份文件在 volume `backups`。只要这两者在,系统可随时重建。
- **worker** 负责耗时工作(排课引擎、发送邮件、PDF/PNG 导出、每日自动备份),与 api 分离,排课时不卡页面。
- 全部跑在**一台主机**,不需要外网、不需要云端账号,校内网络即可使用。

## 两种部署方式

同一份 `docker-compose.yml` 支持两种做法:

1. **拉取官方预建镜像**（推荐，免构建、升级快）：准备 `docker-compose.yml` 和 `.env` 两个文件，然后执行 `sudo docker compose pull && sudo docker compose up -d`。
2. **从源代码自行构建**（需要修改程序或无法连接 GHCR 时）：克隆项目后执行 `sudo docker compose up -d`，首次会在本机构建镜像，通常需要几分钟。

详见 [安装指南](install.md)。

## 名词对照

| 文件用词 | 意思 |
|---|---|
| 主机 / host | 跑 Docker 的那台电脑(校内服务器、台式机、NAS 均可) |
| 容器 container | 一个服务的执行实体,如上图五个 |
| volume | Docker 管理的数据存储区,容器删掉也不会消失 |
| `.env` | 你的配置文件(密码、校名、端口号),**含机密,不要上传到任何地方** |
