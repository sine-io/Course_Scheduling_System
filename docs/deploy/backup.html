DEPLOYMENT GUIDE

备份与恢复

源文件 docs/deploy/backup.md · 在 GitHub 上查看

你的所有数据都在 PostgreSQL。系统提供三道保障:每日自动备份、随时手动备份、恢复(含恢复前自动保护)。备份文件为 PostgreSQL 原生 custom 格式(.dump),存于 Docker volume backups。

一、每日自动备份(默认已开)

  • worker 按 Asia/Shanghai 时区每天 02:00 自动执行一次 pg_dump。
  • 默认保留最新 30 份,超出者由旧到新自动轮替删除。
  • 可在 .env 调整:

ini # 这几项为高级设置,一般保持默认即可;如需调整可加入 .env # BACKUP_HOUR=2 # 每日自动备份的时(0–23) # BACKUP_KEEP=30 # 保留份数 # BACKUP_DIR=/backups

修改后执行 sudo docker compose up -d 生效。

自动备份的文件名形如 backup_20260711_020000_daily.dump。

二、手动备份与恢复(系统管理界面)

登录后到 系统管理 → 数据备份与恢复(限系统管理员):

  • 立即备份:当场生成一份手动备份(文件名 ..._manual.dump)。重大操作(升级、大量导入、学期切换)前建议先按一次。
  • 备份列表:列出所有备份(来源标为「自动 / 手动 / 恢复前保护 / 上传」),可下载、恢复、删除。
  • 上传恢复：上传此前下载的 .dump 文件并恢复，可用于更换主机或异地恢复。非备份格式的文件会被直接拒绝，不影响现有数据。

恢复会发生什么

  1. 系统先自动备份现状(来源标「恢复前保护」),万一恢复的内容不对可再退回。
  2. 以该备份覆盖整个数据库。
  3. 恢复完成后强制所有人重新登录(因为用户数据已被替换)。你会被导回登录页,以恢复时点的账号和密码登录。

恢复是覆盖性操作,请确认选对备份文件再执行。有「恢复前保护」这道自动备份垫底,误操作仍可救回。

三、异地备份(强烈建议)

Docker volume 存在同一台主机。若主机硬盘坏掉,volume 一起没了。 真正安全的备份要放到另一个地方:

做法 1:定期下载备份文件(最简单)

在“数据备份与恢复”中依次点击“立即备份”和“下载”，将 .dump 文件保存到另一台电脑、外接硬盘或云盘。需要恢复时，在新主机上使用“上传恢复”。

超大数据库的恢复走这里,不要用网页上传。 系统对网页上传有 200MB 的请求体上限(避免超大上传打爆主机内存)。若贵校数据库的 .dump 超过此上限,请改用下方「做法 2」的 volume 复制法把备份文件放回容器,再从系统界面「恢复」。

做法 2:把 backups volume 同步到外部(可调度)

备份文件实际存在 volume backups。可用命令把整个备份目录复制到主机文件系统,再由你现有的异地备份机制(rsync、NAS 调度、云端同步)接手:

# 把容器内 /backups 复制到主机当前目录的 ./backups-export
      sudo docker compose cp worker:/backups ./backups-export

反向(把外部备份文件放回系统以便恢复):

sudo docker compose cp ./某份.dump worker:/backups/

放回后即会出现在「备份列表」中,可直接恢复。

四、手动用命令备份 / 恢复(高级)

若你偏好在命令列操作(例如写进自己的调度脚本):

# 备份(pg_dump 在 worker 容器内执行,worker 才装了 postgresql-client)
      sudo docker compose exec worker pg_dump -Fc -h postgres -U scheduler -d scheduler \
        -f /backups/manual_$(date +%Y%m%d_%H%M%S).dump

      # 恢复(会覆盖现有数据;跨版本可能出现可忽略的警告,数据仍正确)
      sudo docker compose exec worker pg_restore --clean --if-exists --no-owner --no-privileges \
        -h postgres -U scheduler -d scheduler /backups/某份.dump

容器内已通过 .env 提供 PGPASSWORD，通常无需另行指定。通过系统界面恢复时，系统会先自动备份并强制所有用户重新登录；命令行方式不会执行这些保护步骤，请谨慎操作。

常见疑问

Q:备份含哪些数据? 全部业务数据(学期、教师、班级、课表、请假、代课、通知、审计记录、系统设置与账号)。不含 Redis(仅队列与 session 时效,可重建)与上传文件暂存。

Q:换一台新主机怎么搬? 新主机照安装指南装好、起好空系统 → 系统管理上传旧主机下载的 .dump 恢复,即完成搬迁。

Q:备份会不会拖慢系统? pg_dump 对线上数据库影响很小,且自动备份排在凌晨。手动备份亦为秒级(视数据量)。
