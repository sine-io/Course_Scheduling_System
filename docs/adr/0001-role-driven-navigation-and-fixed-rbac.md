# 角色驱动导航与固定角色 RBAC

状态：已接受。

系统采用四个固定角色（系统管理员、排课管理员、教务主任、教师）作为权限和界面组织的基础，并允许一个用户拥有多个角色。多角色用户的权限取并集，拥有排课管理职责时默认进入管理视角，不通过切换视角临时改变授权。导航使用“角色默认常用入口 + 用户固定或最近使用入口 + 完整功能目录”的结构；权限在动作级别校验，前端隐藏菜单只改善体验，后端仍是最终授权来源。暂不引入自定义角色编辑器，因为学校职责相对稳定，而任意权限组合会显著增加配置、培训和审计成本。

常用入口按首次成功状态阶段化：首次发布前引导设置、基础数据、教学任务和排课；首次发布后转向仪表盘、课表查询、今日运行和调课代课。角色默认入口最多保留五项，用户可以固定、排序或恢复默认，最近访问只能补充空位。

## 后果

- 角色首页和常用入口可以围绕实际工作任务定制，而不是复制完整菜单。
- 教师可以查看已发布的全校课表，但只能修改本人范围的请假、确认和个人统计相关数据。
- 教务主任可以执行有限的运行操作和查看全校数据，但不能修改核心教学任务、排课草稿或发布课表。
- 系统管理员和排课管理员可以编辑草稿；教务主任只能查看草稿；教师只使用已发布课表。单张已发布课表可供登录用户导出，批量或版本级导出限管理角色。
- 只有当前学期允许常规写入；历史或归档学期默认只读，切换当前学期限系统管理员和排课管理员。
- 发布、删除、备份恢复和权限变更等高风险动作必须保留确认与审计，即使有快捷入口。
- 后续若出现年级、校区或部门隔离需求，应扩展数据范围，而不是立即增加大量新角色。
- 排课管理员和教务主任保持为两个独立角色；兼任者显式授予两个角色，不采用角色合并或自动继承。
