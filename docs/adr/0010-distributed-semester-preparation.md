# 分散的学期准备页面取代设置向导

状态：已接受。

系统不再维护独立的设置向导、向导进度或“设置完成”状态。首次使用从“学期与作息时间表”创建真实学期开始，随后在基础数据、作息分组和校历页面完成各自业务；仪表盘只显示当前学期的数据摘要，排课前置检查和排课准备确认继续作为排课领域的独立业务概念。这样避免一个跨页面流程同时拥有一套重复状态，也让首次准备与日常维护使用同一组页面和权限边界。

## 后果

- `/wizard`、向导 API 和向导持久化状态不再属于运行时产品；历史迁移仅用于解释旧数据库演进，最新迁移删除旧状态表。
- 空学期入口指向学期页面；教室、教师账号、特殊日期等提醒分别指向其所属业务页面，不再汇总到一个完成页。
- “数据摘要”只表达当前学期已有数量，不推导“设置完成”或“可以排课”的结论；排课前置检查和排课准备确认保持各自的权威来源。
- 新部署和用户手册以学期准备页面为起点；已有业务页面不需要兼容旧向导路由。
