# 使用带模板的版本化排课规则

状态：提议。

## 背景

学校规则由教务人员制定，可能随时新增、停用或修改，来源还可能是 Word、Excel 和口头整理。`ref/排课规则.docx` 同时包含全校禁排时段、教师个人日程、科目时段偏好、专用教室要求、单双周安排、国防训练课程以及各年级课时计划。这些内容的对象、强度和可执行程度并不相同。

当前求解器需要稳定的结构化输入，而原文不能直接变成 CP-SAT 约束。若让任意自然语言或任意用户表达式直接执行，会造成含义不确定、规则互相覆盖、历史课表无法重现等问题。

## 决策

排课规则采用“结构化模板 + 原文来源 + 规则集版本”的模型：

1. 人工录入或文件导入先形成规则候选，保留原文、来源位置和解析置信状态。
2. 教务人员确认、修改或停用候选后，形成不可变的规则集版本。
3. 只有系统已有编译器的规则模板才能激活；未支持或有冲突的规则只能作为提醒，不能静默参与排课。
4. 求解器只接收纯结构化规则和编译后的约束，不读取 ORM、Word 文本或任意用户代码。
5. 每次自动排课、课表草稿和发布结果记录所用的规则集版本。

规则强度统一为“必须满足（hard）”“尽量满足（soft）”“仅作记录（informational）”。“不能、要避开、不得”通常进入 hard；“尽量、最好、一般、避免”通常进入 soft；无法确认的语句进入 informational 或待确认状态。

## 不采用的方案

- 不把一个自由文本输入框直接连接到求解器。
- 不把规则存成只有 `key/value` 的散列并让各处自行解释。
- 不允许用户提交 Python、MiniZinc 或其他任意代码作为规则。
- 不让大模型的解析结果自动激活；大模型只能提出候选，原文必须可追溯并由人确认。

## 后果

优点是规则含义、版本和求解结果可以追溯，新增常见规则只需增加模板和编译器；导入文件中的未支持内容也不会被悄悄丢弃。代价是第一版需要维护模板目录，并且复杂的新规则要先扩展领域模型和求解器，不能通过随意写一句话立即生效。

## 迁移边界

`ReferenceSchedulingRule` 继续保存 Word/Excel 的原文快照和导入证据，不作为已生效规则使用。现有 `TeacherTimeRule`、`BlockRule` 和标量 `ConstraintConfig` 通过兼容适配器映射到对应模板；新编辑器写入版本化规则，求解器从同一个版本读取。
