# ADR-0016：将排课工作台作为工作空间入口

状态：已接受（2026-09-20）；关于重复排课页面继续作为独立目的地的条款由 ADR-0017 取代。

## 背景

五步排课流程已经是教务主任反复使用的统一入口，但“开始排课”同时被用作入口名称和第五步动作名称，容易让导航、快捷入口和具体执行动作混淆。后续与排课准备、主流程相关的能力也需要从同一入口承接。

## 决策

- 用户可见的统一入口名称统一为“排课工作台”。
- 该入口与仪表盘同属“工作空间”分组；“排课主流程”保留课程表调整、版本与发布等生成后的收尾页面。
- 内部路由名使用 `scheduling-workbench`。
- 继续保留 `/scheduling/flow` 路径及 `step`、`semester`、`table`、`view` 查询参数，兼容书签、导入后跳转和旧深链接；本次不新增或迁移另一条 URL。
- 五步中的第五步和执行按钮仍称“开始排课”，因为它表示具体动作而非统一入口。
- 原有科目与任课、自动排课、排课规则等页面继续保留其业务能力和权限；它们通过上下文动作返回排课工作台，不作为工作空间中的重复导航入口。学期准备相关能力按 ADR-0018 收纳到工作台辅助工作面。

## 后果

- 导航、仪表盘快捷入口和跨页面回跳使用一致的入口名称，用户可以从工作空间找到整个排课主线。
- 代码中不能再把 `scheduling-flow` 当作路由名称；测试和新链接应使用 `scheduling-workbench`，但 URL 兼容断言仍应覆盖 `/scheduling/flow`。
- 第五步“开始排课”的文案不能整体替换为“排课工作台”，否则会丢失入口与动作的语义区分。
- 将来若需要把课程表调整等页面合并进工作台，应另行评估页面边界和 URL，不在本决策中隐式迁移；三个准备页面的入口收敛由 ADR-0018 单独规定。
