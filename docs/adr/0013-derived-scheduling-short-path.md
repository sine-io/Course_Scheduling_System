# 用统一工作台编排排课业务页面

状态：已接受（流程设计）；关于重复页面和旧深链接继续作为独立目的地的条款由 ADR-0017 取代。

## 背景

参考 MyZan 的五步路径可以降低排课操作的记忆成本，但本项目已经明确采用排课工作台的学期准备辅助工作面、版本化排课规则、独立的排课就绪和直接发布边界。新增一个持久化向导或“设置完成”字段会与这些决策重复并形成竞争状态。

## 决策

提供一个面向当前学期的“排课工作台”，以派生事实编排以下五个可重复使用的步骤：设置班级、设置课时、科目节数、教师任课、开始排课。工作台在同一路由内嵌入各步骤的现有业务组件，步骤完成后可返回总览；生成草稿后进入课程表调整，再执行发布、打印和导出。基础数据、学期与作息等维护入口继续保留；科目与任课、自动排课和排课规则能力继续保留既有页面与深链接，但不再作为侧栏或默认快捷入口与五步主入口并列。所有页面复用同一业务数据和写入接口。

工作台不区分首次和后续排课，只负责业务编排、问题聚合和显示下一步；步骤状态从现有 API 和业务数据计算，不持久化独立流程进度。课表草稿记录生成时的教学任务输入指纹，用于识别输入是否变化；该指纹是课表的生成依据，不是工作流游标。

“规则与预排”不作为排课工作台的独立用户步骤，而是“开始排课”步骤中的高级约束和前置检查。固定/尽量/不排课位、合班和场室准备仍由现有规则与课程表调整边界管理。规则集版本、排课就绪、课表草稿和已发布课表继续由各自的权威边界管理；统一入口在启动前调用现有就绪确认动作，保留同一状态和审计记录。

旧页面作为高级维护入口时，保留原业务标题和有效的学期、步骤、草稿查询上下文，并提供返回“排课工作台”的动作；不强制重定向，以免丢失用户正在处理的定位。工作台、旧页面和结果页面不保存第二套流程游标；输入变化后由当前事实重新计算步骤与排课就绪，受影响草稿标为过期且不自动删除、复制或改写。已发布课表仍是不可变快照。

## 理由

- 复用五步操作顺序和生成后的课程表调整工作台，降低入口发现成本，并让每次排课都使用同一入口。
- 保持 `CONTEXT.md` 中学期准备、排课就绪、规则集版本和发布的独立语义；短路径只把就绪确认编排到“开始排课”动作中，辅助工作面的入口和确认/撤销边界由 ADR-0018 维护。
- 任何导入或规则变化都能由事实重新计算，不需要同步一套容易过期的向导进度。
- 教务主任可以从工作台进入复杂设置；原有页面和深链接继续保留，复杂能力不会被删除，但默认发现路径集中到五步工作台。

## 后果

- 首屏需要读取多个现有摘要/检查接口，并把阻断与提醒统一呈现；这是一层编排，不是新的领域写模型。
- 新建、求解生成或复制的课表会保留教学任务输入指纹；发布检查可以读取当前输入，但不能替换课表生成时的指纹。旧课表没有指纹时状态为未知，不据此回退流程。后续教学任务变化只会使派生阶段待处理，不改写课表快照。
- 原型可以用内存数据展示状态转移，生产实现必须复用现有权限、审计和发布保护。
- 五步工作台流程使用“排课工作台”作为工作空间中的导航语言；页面标题和帮助文案应采用 `CONTEXT.md` 的词汇，不出现仅适用于首次排课的阶段名称。学期、教学任务、规则与预排仍是内部业务概念，不应重新变成必须逐项确认的向导节点。
- 旧排课页面不因导航收敛而改变既有后端权限：教务主任和内置系统管理员按动作权限维护，教师不进入教学任务、规则或草稿维护。隐藏或非默认入口不构成权限边界。
- 草稿生成快照与当前输入不一致时，草稿仍可查询、比较和调整，但不能直接发布；必须基于当前输入重新检查并重新生成。
- 如果未来需要跨学期任务、负责人或 SLA，那是新的业务概念，应另行建模，不能把字段塞进本工作台。

## 拒绝的替代方案

- **恢复一次性设置向导**：会重新引入与分散学期准备重复的完成状态。
- **让导入直接激活规则并创建草稿**：破坏模板导入、规则版本和草稿的隔离边界。
- **用发布前总分代替检查报告**：无法解释硬约束、提醒和未排课时的处理责任。
