# ADR-0018：将学期准备能力收纳为排课工作台辅助工作面

状态：已接受（2026-09-21）。

## 背景

排课工作台已经承接班级、作息、科目、教师、教学任务和自动排课。原先的“学期与作息时间表”“校历与排课准备”“基础数据”三个独立页面仍包含不能删除的学期生命周期、特殊日期、资源、导入和账号绑定能力，但继续作为侧边栏入口会让用户误以为存在第二套排课准备流程。

## 决策

- 侧边栏不再展示三个准备页面；“排课工作台”是学期准备和排课的唯一用户入口。
- 工作台提供三个辅助工作面：
  - “学期管理”承接学期创建、复制、起止日期、作息时间表和班级作息分组；
  - “校历与准备”承接特殊日期、排课前置检查结果以及排课就绪的明确确认和撤销；
  - “资源与导入”承接教室/场地、组合基础数据导入、教师安排模板/参考文件导入和教师登录账号绑定。班级、科目和教师的日常档案维护仍在五步中的对应档案视图完成。
- “开始排课”动作保持既有自动确认就绪行为。需要明确执行或撤销确认时，用户在“校历与准备”辅助工作面完成，使用同一就绪状态、检查和审计记录。
- 原有 `/settings/semesters`、`/settings/calendar` 和 `/basedata` 地址继续保留兼容重定向，保留有效的学期、视图、资源分区和作息表上下文；重定向不是授权边界，目标工作面继续执行原权限检查。
- 辅助工作面复用原页面组件和 API。资源导入或其他会影响排课准备度的提交必须向工作台发出变更通知，工作台重新加载当前学期的摘要、准备度和前置检查数据。

## 理由

- 用户只有一个可发现的准备与排课入口，减少导航歧义和重复维护路径。
- 原页面中没有重复的业务能力不会被删除，只是按职责嵌入同一入口；后端领域模型、接口、来源所有权和审计边界保持不变。
- 显式就绪确认/撤销和自动排课启动的自动确认各自保持清晰语义，避免把“准备完成”误解为课表已发布。
- 旧书签和外部集成仍能定位到等价的工作面，迁移可以渐进完成。

## 后果

- 新导航、空状态、快捷动作和用户手册都必须指向排课工作台及其辅助工作面；不得重新增加三个独立侧边栏入口。
- 组件可以继续保留在 `settings` 或 `basedata` 目录中，代码位置不代表用户入口；后续只有在确认没有工作台引用后才能删除旧组件。
- 任何新增的学期准备能力都必须明确归属五步步骤或三个辅助工作面，并复用现有学期上下文和权限检查。

## 验证

- 前端路由测试覆盖三个旧地址到辅助工作面的重定向和查询参数保留。
- 工作台测试覆盖学期、校历和资源辅助入口、返回行为以及资源提交后的变更通知。
- 前端定向测试与生产构建必须通过；用户手册、`CONTEXT.md`、架构规划和相关 UX 规格同步描述五组导航。
