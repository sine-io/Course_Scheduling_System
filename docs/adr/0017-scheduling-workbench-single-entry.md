# ADR-0017：排课工作面只保留在排课工作台

状态：已接受（2026-09-20）；学期准备页面的入口与辅助工作面由 ADR-0018 进一步明确。

## 背景

排课工作台已经嵌入班级、作息、科目、教师、教学任务和自动排课能力。继续保留功能完全相同的独立页面，会形成多个可发现入口、重复维护路径和不一致的上下文跳转，也让用户无法判断哪个页面是权威工作面。

基础数据、学期与作息时间表等旧页面还混有两类职责：一类已由工作台完整承接，另一类是导入、教室/场地、学期生命周期、特殊日期或账号绑定等不同业务能力。收敛入口不能删除后一类能力，也不能改变权限、数据模型或导入边界。

## 决策

- 排课工作台是班级、作息、科目档案、教师档案、教学任务和自动排课的唯一用户工作面。
- `/basedata?tab=classes|subjects|teachers`、`/scheduling/assignments`、`/scheduling/auto` 和 `/settings/period-tables/:id` 保留为兼容地址，并重定向到工作台的对应步骤；有效的学期、档案/任课视图和作息表上下文继续传递。
- 基础数据页不再提供班级、科目或教师 CRUD，只保留组合与来源导入、教室/场地维护，以及管理员专用的教师登录账号绑定。账号绑定使用既有教师更新接口和完整对象，不另建教师维护模型。
- 工作台可以复用原页面组件和 API。共享代码、导入写入同一模型以及旧地址兼容重定向都不构成第二个用户工作面。
- 排课规则、课程表调整、版本与发布、课表查询等职责与五步流程不完全重复，继续保留独立页面；学期生命周期、校历、导入、资源维护和账号绑定由工作台辅助工作面承接，旧地址仅作兼容重定向。
- 路由重定向只负责兼容定位，不是授权边界；目标页面继续执行原有角色和动作权限检查。

## 理由

- 一个业务动作只有一个权威工作面，导航、空状态、快捷动作和文档不再把用户带到不同实现。
- 兼容旧书签和已有跨页面链接，同时允许逐步删除旧页面组件而不破坏外部地址。
- 按业务能力拆分基础数据责任，保留仍然必要且没有在工作台五步中重复的导入、资源和账号管理，并以工作台辅助面提供。
- 不改变后端领域模型、接口、审计和导入来源所有权，收敛范围限定在用户入口与页面职责。

## 后果

- 新链接和测试必须以 `scheduling-workbench` 路由及对应 `step`、`view`、`semester`、`table` 查询参数为准。
- 旧独立页面组件在仍被工作台复用时可以保留；不再被复用的组件可在后续确认无引用后删除。
- 资源与导入辅助面的教师账号绑定必须保持独立、窄化的界面，不能重新暴露教师新增、编辑、删除或排课设置。
- ADR-0013、ADR-0014 和 ADR-0016 中关于重复页面继续作为独立高级维护入口的描述由本决策取代；关于三个准备页面入口和就绪确认语义的细化以 ADR-0018 为准，其余派生状态、五步流程、命名和导航分组决策继续有效。
